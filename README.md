# 팔로워 트래커

여러 SNS의 팔로워 수와 변화를 휴대폰에 기록하고 홈 화면 위젯에서 확인하는 무료 모바일 앱을 개발한다. 사용자가 앱 내부에서 로그인한 SNS 세션으로 데이터를 읽고 기기에 보관한다. 전체 명단을 검증할 수 있는 SNS에서는 언팔로우 추정과 맞팔 상태를 제공한다.

Android·iOS 네이티브 앱과 위젯을 구현 중이다. SNS별 세션 수집과 실제 기기 위젯 동작의 검증 상태는 구현 기록에 남긴다.

2026-10-21에는 Instagram 페이지 자체의 프로필 응답을 읽어, 정확한 수치가 DOM에 남지 않는 로그인에서도 자동 연결하도록 보완했다. 새 로그인 창마다 적용하며 추가 API 요청이나 이전 값의 재사용으로 성공을 만들지 않는다. [수집 원인·변경과 재로그인 검증 범위](docs/INSTAGRAM_LOGIN_COLLECTION.md)

Android에서는 SNS 개인 계정을 연결한 뒤 **설정 → 수집 설정 → 빠른 추적 시작**으로 짧은 간격의 수집을 실행할 수 있다. 프로필 브라우저 반복 경로를 다섯 SNS의 개인 프로필과 명시적으로 연결한 Facebook 페이지에 적용한다. 실제 성공 여부는 SNS 응답과 로그인 상태에 따라 기록하며, 확인·재로그인이 필요한 계정은 마지막 정상값을 유지한다. Facebook 페이지는 최초에 사용자가 대상을 선택하고 확인하며, 이후에는 저장된 페이지와 로그인 소유자를 따로 검증해 반복 수집한다. 기존 로그인 세션으로 공식 본인 프로필의 정확한 수를 새로 읽고, 저장 직후 홈 화면 위젯 갱신을 요청한다. 실행 중 알림이 표시되고 한 번에 최대 약 6시간 실행한다. 일반 수집 요청은 Android·iOS 모두 별도 설정 없이 15분 간격으로 고정한다. 기존 간격 선택 항목은 제거하며 Android는 앱 시작 시 이전 예약을 갱신한다. 실제 실행과 수집 성공은 운영체제·네트워크·SNS 요청 제한에 따라 늦어질 수 있다.

Android·iOS의 주요 화면은 **계정·분석·위젯·설정** 네 탭이다. 계정 탭은 연결된 SNS별 팔로워 수·변화·수집 시각과 상세 기록을 보여준다. 분석 탭에서 계정을 선택해 관계 명단을 비교하고, 위젯 탭에서 구성을 미리 보고 추가 방법을 확인한다. 수집 설정·연결 관리·도움말·데이터 안내·앱 지원은 설정 탭에서 연다. 앱 지원은 무료 기능과 준비 중인 운영 방식을 안내하며 실제 광고·결제·구독은 제공하지 않는다. [화면과 탐색 설계](docs/UI_UX.md)

홈 위젯은 **내 계정**과 **소셜 모아보기** 두 종류로 구성한다. Android는 계정 하나의 최소 2×1 가로 위젯과 모든 연결을 스크롤로 확인하는 대형 위젯을 제공한다. iOS는 가로형 `systemMedium`과 대형 `systemLarge`로 구분한다. 큰 SNS 아이콘과 우측 팔로워 수를 중심으로 표시하고, 계정명은 위젯별로 켜고 끌 수 있으며 기본값은 숨김이다. 증감·팔로잉·직전 수는 위젯에서 제외하고 실제 수집 시각을 유지한다. 대형에 모든 연결이 들어가지 않으면 이전·다음 버튼으로 개인 계정과 Facebook 페이지를 모두 확인한다. 공식 로고·SNS 색상·실제 수집 시각을 사용하며 새 수집 요청을 추가하지 않는다. [위젯 디자인과 검증 범위](docs/WIDGET_DESIGN.md)

**SNS 연결 → Facebook 페이지**에서 페이지 주소를 입력하고 **연결**을 누르면 로그인 뒤 대상 페이지로 이어서 이동해 정확한 수를 확인한다. 일반 주소는 별도 확인 없이 연결하며, 공유 링크나 Facebook에서 직접 찾은 대상은 **이 페이지 연결**로 확정한다. 개인 프로필과 여러 페이지의 기록을 구분하고 계정 카드·위젯에 페이지 이름을 표시한다. Android는 연결한 페이지를 반복 수집에 포함한다. iOS는 연결 직후 네이티브 요청으로 같은 페이지의 정확한 수를 새로 확보한 경우 자동 수집 대상으로 삼는다. 확보하지 못하면 브라우저에서 읽은 실제 값과 시각을 유지하며 전경 갱신으로 표시한다. 실제 페이지·백그라운드 갱신의 검증 상태는 별도로 기록한다. [페이지 연결과 저장 경계](docs/FACEBOOK_PAGES.md)

Facebook 페이지의 이름 주소·숫자 ID 주소 전환은 입력한 대상과 문서의 이름·ID를 함께 확인한다. 같은 페이지의 JSON 조각에 흩어진 수치는 순서와 관계없이 결합하며, 페이지 증거 없는 수치나 충돌하는 값은 저장하지 않는다. 이름이 늦게 준비되는 경우에는 추가 API 요청 없이 같은 문서를 다시 읽는다.

AI Quota의 1분 수집·상시 서비스·위젯 갱신 구조를 코드로 비교했다. 일반 모드는 `dataSync`를 유지하고, API 34 이상 디버그 앱에는 명시적으로 켜는 **프리미엄 위젯 시험 모드**를 추가했다. 시험 모드는 `specialUse`로 약 1분마다 수집하며 자체 6시간 종료를 적용하지 않는다. 앱에서 시작한 뒤 홈 위젯과 실행 알림으로 확인하고 중지할 수 있다. 실제 결제 권한·배포 승인이나 24시간 연속 성공을 뜻하지 않으며 Release 앱에는 시험 서비스 선언이 포함되지 않는다. [AI Quota 갱신 구조와 시험 경계](docs/WIDGET_REFRESH_REFERENCE.md)

장시간 관찰에 앞서 실제 서비스와 공유하는 수집 루프를 가상 시계로 실행하는 코드 실험을 추가했다. 다섯 SNS의 24·72시간 반복과 요청 제한·오프라인·인증 만료·중지·복구를 검사한다. 실험에서 기한 전 내부 수집 호출과 재시도 불가 계정이 만드는 불필요한 대기를 재현해 수정했다. 실제 SNS·기기 결과와 구분한 [코드 실험과 재현 명령](docs/CODE_EXPERIMENTS.md)을 참고한다.

2026-10-19에는 앱 복귀·업데이트·재부팅 때 남은 프리미엄 실행 요청을 복구하고, 루프 취소 후 잘못된 실행 상태와 네트워크 callback 누락에 따른 무한 대기를 보완했다. 계정 상세·연결 관리의 **로그아웃**은 로그인 정보만 해제하고 수집·관계 기록을 유지한다. 작은 위젯에는 팔로잉 수 또는 실제 직전 팔로워 수를 추가했다. [코드 수정과 아직 남은 실기기 검증](docs/CONTINUITY_AND_LOGOUT.md)

SNS 공통 경로에 오프라인 자동 요청 생략, 최신 응답 재확인, 연결·세션 준비 재사용, 위젯의 최신 두 기록 조회와 갱신 병합, 디버그 계측을 적용했다. Android의 검증된 프로필 브라우저 수집은 빠른 추적 중 WebView를 재사용하고 수집 후 빈 페이지로 전환한다. 기존 기록·수집 지원 범위·1분 간격은 유지하며 실기기의 절감률은 아직 측정하지 않았다. [적용 범위와 측정 한계](docs/RESOURCE_EFFICIENCY.md)

프로필 정보 준비 실패와 로그인 만료를 구분한다. Android에서 기존 로그인 문맥이 확인된 프로필은 최대 15초 동안 로컬 정보 준비를 기다린다. 브라우저 수집의 일시적인 문서 읽기 실패는 마지막 정상 기록을 유지하고 1·2·4·8·15분으로 대기를 늘리며 재시도한다. 네이티브 응답 형식 오류는 15분을 기다리며, 직접 갱신은 이 로컬 대기를 건너뛸 수 있다. 실제 로그인 페이지 이동·HTTP 401·계정 불일치·추가 인증과 서버 요청 제한은 별도로 처리한다. TikTok·Facebook의 기존 세션으로 재로그인 없이 새 관측 저장과 자동 수집 경로 회복을 실기기에서 확인했다. [세션 유지와 수집 실패 복구](docs/DEVICE_VALIDATION.md#android-세션-유지와-수집-실패-복구--2026-10-05)

새 수집의 성공에는 네트워크 연결, SNS의 유효한 세션과 정확한 프로필 응답, 운영체제의 실행 허용이 필요하다. 외부 SNS의 응답·인증과 모바일 실행 조건을 앱이 통제하지 못하므로 모든 상황에서 100% 수집이나 정확한 1분 실행을 보장하지 않는다. 실패 시 마지막 정상값과 실제 수집 시각을 보존하며, 이전 값을 새 관측으로 기록하지 않는다.

2026-10-17~18 실기기에서 Facebook의 단수 `follower`·공백 없는 숫자 라벨과 TikTok의 생략된 로그인 사용자 문맥을 보완했다. 캡처 수정본의 실제 1분 서비스에서 앱을 홈으로 내린 채 Instagram·X·TikTok·Facebook 각각 약 11분간 12회 연속 새 관측을 저장했다. 기존 연결 ID·정확한 수를 검증하고 새 계정 연결의 로그인 요건을 유지한다. 실제 Instagram·Facebook 홈 위젯의 최신 수치·시각 일치와 위젯 추가 시 선택 계정 저장도 확인했다. [실기기 검증과 남은 범위](docs/DEVICE_VALIDATION.md#android-개인-프로필-반복-수집과-위젯-계정-선택--2026-10-17)

빠른 추적을 끈 뒤의 일반 예약에서는 WorkManager 2.10.5가 차단된 백그라운드 네트워크를 사용 가능으로 판단하는 문제를 확인했다. 공식 수정이 포함된 2.11.2와 의존성 잠금을 적용했고 빌드·회귀 검사를 통과했다. 실제 수정본은 차단 상태에서 요청을 시작하지 않고 대기한다. 일반 15분 예약의 수정 후 실제 수집은 기기 발열 보호 해제 뒤 확인할 범위다. [일반 예약의 네트워크 제약](docs/DEVICE_VALIDATION.md#빠른-추적-후-일반-예약의-네트워크-제약--2026-10-18)

개인 계정의 반복 수집에서는 계정별 예외를 분리해 나머지 SNS 수집을 계속하고, 일반 예약도 남은 계정 처리 후 실패 여부를 반환한다. Facebook 개인 프로필의 `data-sjs` JSON과 정확한 텍스트 span 표시를 읽으며 본인 식별·축약값·피드 경계는 유지한다. Android의 로컬 프로필 읽기는 Promise 대기 없이 같은 문서를 한 번 읽고, JavaScript 응답 대기와 추적 중지 시 취소를 구분한다. 페이지 기능은 후속 범위다. [반복 수집 코드의 경계](docs/DEVICE_VALIDATION.md#android-개인-계정-반복-수집-코드-보완--2026-10-05)

초기 API 36 에뮬레이터에서 앱 화면을 닫은 채 약 7분 동안 Instagram 8회 연속 수집과 실제 위젯 반영을 확인했다. SNS 요청 제한·잠금·절전·실기기 조건과 24시간 연속 1분 수집을 보장하는 결과는 아니다. 후속 다중 SNS 실기기 결과와 남은 범위는 기기별로 기록한다. [실제 시험 범위](docs/DEVICE_VALIDATION.md)

후속 잠금·배터리 절약 시험에서는 스와이프 잠금과 SDK로 활성화한 배터리 절약 상태에서 각각 약 6분 동안 새 수집 6회를 관찰했다. 잠금 해제 후 앱을 열기 전에 기존 홈 위젯의 새 수집 시각도 확인했다. 이 결과는 API 36 에뮬레이터의 짧은 시험이며 비밀번호 잠금·실기기·장시간·모든 절전 조건의 1분 갱신을 보장하지 않는다. [잠금·배터리 절약 검증](docs/DEVICE_VALIDATION.md#android-스와이프-잠금과-배터리-절약-중-빠른-추적--2026-10-03)

별도의 실제 네트워크 단절 시험에서도 마지막 정상 수치·시각을 유지했고, 자동 재시도 대기가 1·2·4분으로 늘어나는 것을 확인했다. 네트워크 복귀 후 저장된 대기를 지켜 앱 화면을 열지 않고 3회 수집을 재개했으며 홈 위젯도 새 수집 시각으로 바뀌었다. 이 동안 실제 팔로워 수의 증감은 관측하지 않았다. [단절·복구 검증](docs/DEVICE_VALIDATION.md#android-실제-네트워크-단절과-위젯-복구--2026-10-02)

일반 예약도 Android API 36 에뮬레이터에서 확인했다. 재부팅 뒤 기존 세션으로 수·완료 명단을 새로 확보했고, 앱과 빠른 추적을 닫은 상태에서 15분 설정의 예약 수집 두 번과 홈 위젯 시각 반영을 관찰했다. 실제 관측 간격은 약 16분 33초와 15분 56초였으며, 시험 후 원래 60분 설정으로 복원했다. 실기기·절전·24시간 결과는 별도 검증이 필요하다. [일반 예약·재부팅 검증](docs/DEVICE_VALIDATION.md#android-일반-예약과-재부팅-후-복구--2026-10-03)

강제 Doze 시험에서는 약 19분 동안 마지막 정상 기록과 위젯 시각을 유지했고, 해제 뒤 앱을 열지 않고 일반 예약 수집을 재개했다. 이때 이전 기록과 다른 수치·증감 및 새 수집 시각이 실제 홈 위젯에 반영됐다. 시험 후 60분 예약과 정상 절전 상태로 복원했다. 이는 개발 도구로 제어한 에뮬레이터 결과이며 자연 절전·잠금·실기기 결과는 별도 확인이 필요하다. [Doze·변경값 반영](docs/DEVICE_VALIDATION.md#android-강제-doze와-실제-위젯-변화--2026-10-03)

Android의 강제 중지 시험에서는 약 17분 동안 수집이 멈추고 정상 기록·세션이 보존됐다. OS가 홈 위젯을 회색으로 비활성화했으며, 앱을 한 번 다시 연 뒤 일반 예약과 위젯 표시가 복구됐다. 빠른 추적은 사용자가 다시 시작한다. 위젯 탭과 도움말에 복구 방법을 안내한다. 이 결과는 API 36 에뮬레이터의 SDK 시험이며 실기기·장시간 결과와 구분한다. [강제 중지·재개 검증](docs/DEVICE_VALIDATION.md#android-강제-중지와-앱-재개-후-복구--2026-10-03)
