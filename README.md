# 팔로워 트래커

여러 SNS의 팔로워 수와 변화를 휴대폰에 기록하고 홈 화면 위젯에서 확인하는 무료 모바일 앱을 개발한다. 사용자가 앱 내부에서 로그인한 SNS 세션으로 데이터를 읽고 기기에 보관한다. 전체 명단을 검증할 수 있는 SNS에서는 언팔로우 추정과 맞팔 상태를 제공한다.

Android·iOS 네이티브 앱과 위젯을 구현 중이다. SNS별 세션 수집과 실제 기기 위젯 동작의 검증 상태는 구현 기록에 남긴다.

Android에서는 SNS 개인 계정을 연결한 뒤 **설정 → 수집 설정 → 빠른 추적 시작**으로 짧은 간격의 수집을 실행할 수 있다. Instagram에 한정됐던 프로필 브라우저 반복 경로를 다섯 SNS의 개인 프로필에 적용한다. 실제 성공 여부는 SNS 응답과 로그인 상태에 따라 기록하며, 확인·재로그인이 필요한 계정은 마지막 정상값을 유지한다. Facebook 페이지는 별도 수동 갱신 흐름을 유지한다. 기존 로그인 세션으로 공식 본인 프로필의 정확한 수를 새로 읽고, 저장 직후 홈 화면 위젯 갱신을 요청한다. 실행 중 알림이 표시되고 한 번에 최대 약 6시간 실행한다. 일반 수집 요청은 Android·iOS 모두 별도 설정 없이 15분 간격으로 고정한다. 기존 간격 선택 항목은 제거하며 Android는 앱 시작 시 이전 예약을 갱신한다. 실제 실행과 수집 성공은 운영체제·네트워크·SNS 요청 제한에 따라 늦어질 수 있다.

Android·iOS의 주요 화면은 **계정·분석·위젯·설정** 네 탭이다. 계정 탭은 연결된 SNS별 팔로워 수·변화·수집 시각과 상세 기록을 보여준다. 분석 탭에서 계정을 선택해 관계 명단을 비교하고, 위젯 탭에서 구성을 미리 보고 추가 방법을 확인한다. 수집 설정·연결 관리·도움말·데이터 안내·앱 지원은 설정 탭에서 연다. 앱 지원은 무료 기능과 준비 중인 운영 방식을 안내하며 실제 광고·결제·구독은 제공하지 않는다. [화면과 탐색 설계](docs/UI_UX.md)

Android의 **SNS 연결 → Facebook 페이지**는 로그인 후 사용자가 추적할 페이지를 열고 **연결 확인**을 눌러 수집하는 별도 흐름이다. 개인 프로필과 여러 페이지의 기록을 구분하고 계정 카드·위젯에 페이지 이름을 표시한다. 현재는 전경 수집이며 실제 페이지·백그라운드 갱신의 검증 상태는 별도로 기록한다. [페이지 연결과 저장 경계](docs/FACEBOOK_PAGES.md)

AI Quota의 1분 수집·상시 서비스·위젯 갱신 구조를 코드로 비교했다. AI Quota의 `specialUse`와 현재 앱의 `dataSync`는 실행 제한과 적용 조건이 다르다. 24시간 연속 1분 갱신은 아직 구현·검증 완료로 표시하지 않는다. [AI Quota 갱신 구조 참고](docs/WIDGET_REFRESH_REFERENCE.md)

SNS 공통 경로에 오프라인 자동 요청 생략, 최신 응답 재확인, 연결·세션 준비 재사용, 위젯의 최신 두 기록 조회와 갱신 병합, 디버그 계측을 적용했다. Android의 검증된 프로필 브라우저 수집은 빠른 추적 중 WebView를 재사용하고 수집 후 빈 페이지로 전환한다. 기존 기록·수집 지원 범위·1분 간격은 유지하며 실기기의 절감률은 아직 측정하지 않았다. [적용 범위와 측정 한계](docs/RESOURCE_EFFICIENCY.md)

초기 API 36 에뮬레이터에서 앱 화면을 닫은 채 약 7분 동안 Instagram 8회 연속 수집과 실제 위젯 반영을 확인했다. SNS 요청 제한·잠금·절전·실기기 조건과 24시간 연속 1분 수집을 보장하는 결과는 아니다. 후속 다중 SNS 실기기 결과와 남은 범위는 기기별로 기록한다. [실제 시험 범위](docs/DEVICE_VALIDATION.md)

후속 잠금·배터리 절약 시험에서는 스와이프 잠금과 SDK로 활성화한 배터리 절약 상태에서 각각 약 6분 동안 새 수집 6회를 관찰했다. 잠금 해제 후 앱을 열기 전에 기존 홈 위젯의 새 수집 시각도 확인했다. 이 결과는 API 36 에뮬레이터의 짧은 시험이며 비밀번호 잠금·실기기·장시간·모든 절전 조건의 1분 갱신을 보장하지 않는다. [잠금·배터리 절약 검증](docs/DEVICE_VALIDATION.md#android-스와이프-잠금과-배터리-절약-중-빠른-추적--2026-10-03)

별도의 실제 네트워크 단절 시험에서도 마지막 정상 수치·시각을 유지했고, 자동 재시도 대기가 1·2·4분으로 늘어나는 것을 확인했다. 네트워크 복귀 후 저장된 대기를 지켜 앱 화면을 열지 않고 3회 수집을 재개했으며 홈 위젯도 새 수집 시각으로 바뀌었다. 이 동안 실제 팔로워 수의 증감은 관측하지 않았다. [단절·복구 검증](docs/DEVICE_VALIDATION.md#android-실제-네트워크-단절과-위젯-복구--2026-10-02)

일반 예약도 Android API 36 에뮬레이터에서 확인했다. 재부팅 뒤 기존 세션으로 수·완료 명단을 새로 확보했고, 앱과 빠른 추적을 닫은 상태에서 15분 설정의 예약 수집 두 번과 홈 위젯 시각 반영을 관찰했다. 실제 관측 간격은 약 16분 33초와 15분 56초였으며, 시험 후 원래 60분 설정으로 복원했다. 실기기·절전·24시간 결과는 별도 검증이 필요하다. [일반 예약·재부팅 검증](docs/DEVICE_VALIDATION.md#android-일반-예약과-재부팅-후-복구--2026-10-03)

강제 Doze 시험에서는 약 19분 동안 마지막 정상 기록과 위젯 시각을 유지했고, 해제 뒤 앱을 열지 않고 일반 예약 수집을 재개했다. 이때 이전 기록과 다른 수치·증감 및 새 수집 시각이 실제 홈 위젯에 반영됐다. 시험 후 60분 예약과 정상 절전 상태로 복원했다. 이는 개발 도구로 제어한 에뮬레이터 결과이며 자연 절전·잠금·실기기 결과는 별도 확인이 필요하다. [Doze·변경값 반영](docs/DEVICE_VALIDATION.md#android-강제-doze와-실제-위젯-변화--2026-10-03)

Android의 강제 중지 시험에서는 약 17분 동안 수집이 멈추고 정상 기록·세션이 보존됐다. OS가 홈 위젯을 회색으로 비활성화했으며, 앱을 한 번 다시 연 뒤 일반 예약과 위젯 표시가 복구됐다. 빠른 추적은 사용자가 다시 시작한다. 위젯 탭과 도움말에 복구 방법을 안내한다. 이 결과는 API 36 에뮬레이터의 SDK 시험이며 실기기·장시간 결과와 구분한다. [강제 중지·재개 검증](docs/DEVICE_VALIDATION.md#android-강제-중지와-앱-재개-후-복구--2026-10-03)
