# 모든 SNS의 수집 우선순위

사용자 결정: **1순위는 지속·장기 수집과 세션 유지, 2순위는 배터리·데이터 사용량 최소화**다. Instagram·TikTok·X·Facebook 개인 프로필·Facebook 페이지·Reddit·YouTube 모두에 적용한다.

## 먼저 유지할 동작

- 로그인·연결 정보를 기기에 보관하고 매 수집에서 현재 세션을 사용한다. 일시적인 문서 미준비나 형식 오류를 임의 로그아웃으로 바꾸지 않는다.
- 저장은 같은 계정·페이지·채널의 새 실제 응답에만 허용한다. 마지막 정상 수와 시각은 실패 때 유지하며 이전 값을 새 성공으로 기록하지 않는다.
- 요청 제한은 서버의 대기 기한을 지킨다. 실제 인증 만료·추가 인증·계정 불일치는 사용자 확인을 요구한다. 다른 경로로 제한을 즉시 우회하거나 쿠키 만료를 임의 연장하지 않는다.
- 사용자 로그아웃·연결 해제·세션 교체와 취소를 존중한다. 이전 작업의 늦은 응답으로 연결이나 쿠키를 복원하지 않는다.
- 한 SNS의 오류가 다른 SNS의 반복 수집을 중단하지 않도록 실패를 분리한다. 앱 화면 종료·자원 회수 뒤에는 저장한 로그인과 기존 기록으로 다음 수집을 준비한다.

Android에서 Instagram·TikTok의 세션 HTTP 응답 형식이 바뀌었지만 같은 로그인이 유효하면, 같은 프로필의 공식 브라우저 읽기를 한 번 시도한다. 성공한 경로만 이후 반복 수집 경로로 저장한다. 기존에 브라우저를 사용하는 X·Facebook·페이지·YouTube는 해당 경로를 계속 사용한다. Reddit은 검증한 세션 HTTP 경로를 유지하며 지원하지 않는 브라우저 판독을 성공으로 취급하지 않는다. 서버 제한·오프라인·인증 오류·추가 인증에는 이 추가 요청을 실행하지 않는다.

## 그다음 줄일 비용

수치 요청은 새 관측을 확인하고, 변경되지 않는 정적 스크립트·폰트와 연결 준비는 재사용한다. 브라우저 이미지는 수집에 필요하지 않을 때 차단하고 미디어 자동 재생을 허용하지 않는다. 수집을 마친 재사용 WebView는 빈 문서로 전환해 활성 페이지를 유지하지 않으며 쿠키·로그인 저장소를 지우지 않는다. 전역 `pauseTimers()`처럼 다른 로그인 창까지 멈출 수 있는 최적화는 사용하지 않는다.

위젯은 저장한 실제 값을 표시하고 최신 두 기록만 읽으며 갱신 요청을 병합한다. 위젯 렌더링 때문에 별도 SNS 요청을 만들지 않는다. 위젯의 작은 크기·계정명 표시 옵션은 수집 주기를 바꾸지 않는다.

## 검증의 구분

여섯 SNS의 가상 반복 루프는 요청 시점·72시간 실행·계정별 오류·제한·인증 만료·취소와 복구 정책을 검사한다. 이 실험은 실제 SNS의 세션 수명을 측정하지 않는다. Android의 일반 15분 요청과 빠른 추적·프리미엄 시험 모드, iOS 예약의 실행 한계는 기존 정책을 따른다. 배터리·데이터 사용량 감소율과 실제 24시간 연속 수집은 해당 기기에서 측정한 뒤에만 보고한다.
