# Instagram 로그인 후 정확한 수집

2026-10-21. 로그인 직후 수치를 한 번 읽는 것과, 로그아웃 뒤 새로 로그인해도 자동 연결하는 것을 별도 검증한다. 개인 계정명·ID·팔로워 수·쿠키·원시 응답은 진단 출력과 저장소에 남기지 않는다.

## 확인한 원인

실제 로그인 세션과 본인 ID는 유효했으나 해당 프로필 문서에는 정확한 팔로워 수가 남지 않고 축약된 DOM 표시만 있었다. 페이지가 자체적으로 받은 GraphQL 응답에는 정확한 본인 수치가 있었다. 기존 캡처가 이 응답을 놓치고 추가 API 요청으로 넘어가면 429가 발생해 자동 연결하지 못했다.

## 변경

- 새 Instagram 로그인 WebView마다 사이트 스크립트보다 먼저 응답 관찰을 설치한다. Android의 반복 수집용 프로필 브라우저에도 같은 관찰을 설치한다. Android는 WebKit의 `DOCUMENT_START_SCRIPT` 지원 여부를 확인하며, 미지원 환경에서는 기존 캡처 경로를 유지한다. iOS는 새 로그인 WKWebView의 메인 문서에 설치한다.
- 사이트의 기존 fetch/XHR가 받은 공식 프로필·GraphQL 응답만 읽는다. 추가 요청을 보내거나 요청 본문·요청 헤더·입력 폼을 읽지 않는다. 원래 fetch Promise·Response와 사이트의 본문 읽기를 유지한다. Google 등의 인증 문서·자식 프레임에는 설치하지 않는다.
- 응답에서 프로필 ID·사용자명·표시 이름·정확한 팔로워/팔로잉 수만 골라 문서 메모리에 최대 16개 보관한다. 쿠키의 본인 ID와 일치하는 정확한 정수만 기존 캡처기가 사용한다. fetch 복제 응답은 최대 4 MiB·5초, JSON 탐색은 최대 100,000개로 제한한다. 크기 초과 때 원래 소비자를 기다리는 취소 Promise에 매달리지 않도록 관찰용 reader와 타이머를 즉시 정리한다. 이 정리 실패를 회귀에서 먼저 재현한 뒤 수정했다. 축약값·음수·다른 계정·429·로그인으로 이동한 응답을 성공으로 바꾸지 않는다.
- 관찰값은 15초 뒤 또는 문서 주소가 달라지면 버린다. 새 로그인 창에는 새 관찰 저장소가 만들어진다. 로그아웃은 기존처럼 해당 SNS의 세션·쿠키·웹 저장소를 정리하고, 수집·관계 기록은 유지한다. 이전 수치를 새 관측으로 복사하지 않는다.
- 정확한 본인 정보가 준비되면 기존 자동 연결 콜백과 ViewModel 저장 경로를 실행한다. 개인 프로필에는 `연결 확인` 버튼을 추가하지 않는다. Facebook 페이지의 명시적 대상 확인 흐름은 별도다.

## 확인한 범위

- 공유 Node 회귀 72개: 원래 응답과 인수 보존·추가 요청 없음·본인 확인·정확도·429·외부 호스트·인증 페이지·만료·문서 주소 변경·크기/개수 제한을 통과했다.
- Android core 45개, app Debug/Release 각 106개, Debug/테스트 APK·Release/R8·두 lint를 통과했다. lint 오류는 없으며 WebKit 의존성 적용 뒤 경고는 각각 16개다. 기존 벡터/UseKtx 경고 8개와 WebViewClient 관련 경고 8개를 구분한다.
- 새 빈 검증 앱의 실제 WebView에서 새 문서의 응답 수치 변경·원래 응답 읽기·Google 문서 미설치·세 차례 재로그인과 Facebook 페이지 회귀 총 7개를 skip 없이 통과했다. 실제 SNS 응답을 대신한 로컬 HTTPS fixture다.
- 실기기의 기존 Instagram 세션에서 정확한 본인 수치를 읽었다. 이어 실제 로그인 Dialog→자동 연결 콜백→ViewModel→계정·새 관측 저장을 확인했다. 쿠키 본인 ID 일치와 세션 메타데이터 저장도 확인했으며 DB에 시험 값을 넣지 않았다.
- 실제 앱의 로그아웃 뒤 계정 ID·연결 시각·수집 기록 보존, 인증 필요 상태와 세션 메타데이터 제거를 확인했다. 사용자가 실제로 다시 로그인한 뒤 확인 버튼 없이 자동 연결됐다고 확인했다. 읽기 전용 DB 검사에서도 기존 키·연결 시각·기록을 유지하고 새 자동 연결 관측과 후속 프로필 브라우저 관측을 저장했으며 상태는 READY였다. 이 두 관측의 간격은 약 284초로, 1분 지속 서비스나 24시간 수집을 검증한 결과와 구분한다.
- 후속 실제 프리미엄 추적에서는 앱을 홈으로 내린 27분 동안 새 관측 28개를 저장했다. 간격 중앙값 59.947초·최대 60.579초이며 실제 수치 변화도 관측했다. 같은 실행의 내 계정 1×1·모아보기 대형 홈 위젯에서 최신 DB의 정확한 수와 수집 시각 일치를 확인했다. [기기·시각·남은 한계](DEVICE_VALIDATION.md#android-instagram-재로그인-후-프리미엄-추적과-두-홈-위젯--2026-10-2122)
- iOS Debug `build-for-testing`와 서명 없는 Release 빌드를 통과했다. iOS 실제 로그인·팝업·위젯과 장시간 수집 결과는 아니다.

`AutoConnectionRuntimeTest.instagramLogoutAndFreshLoginWindowsConnectWithNewCountsAutomatically`는 별도 검증 패키지에서만 세 차례의 합성 로그인→자동 연결→로그아웃→새 창을 실행한다. 매회 다른 정확한 수치와 마지막 0을 확인하고, 인증 없는 프로필 응답은 연결하지 않으며 수동 연결 확인 없이 회당 한 번만 콜백을 전달하는지 검사한다. 새 `dev.datell.followertracker.loginvalidation` 앱에서 응답 관찰 검사와 함께 2개를 skip 없이 실제 실행해 통과했다. 첫 로드부터 네트워크를 차단하고 HTTPS fixture 응답만 허용했다. 기존 검증 앱에서 실제 로그인 상태가 감지돼 멈춘 검사는 성공으로 계산하지 않고, 그 세션을 지우거나 덮지 않았다. 이 회귀와 실제 사용자의 재로그인 결과를 구분한다.

로그·개인 백업·시험 APK는 `.local/device-qa/`에만 보관하고 Git에 포함하지 않는다.
