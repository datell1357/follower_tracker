Reddit의 계정 인증 전 세션 후보 쿠키 발급도 관측했다. 쿠키 존재는 로그인 성공으로 기록하지 않는다. 진단은 입력값·쿠키 값·DOM 원문을 저장하지 않으며 로컬 결과는 `.local/evidence/login-2026-10-01/official-login-pages-final.json`에 있다. 테스트 뒤 사용자가 직접 로그인할 수 있도록 독립 에뮬레이터에서 앱을 실행해 두었다.

본인 계정의 로그인은 앱 안의 공식 SNS 페이지에서 사용자가 직접 진행한다. 비밀번호·쿠키·원시 명단은 채팅이나 저장소에 전달하지 않는다. 실기기 종류와 시험할 SNS가 정해지면 아래 순서로 결과를 기록한다.

1. OS·앱·WebView 버전, SNS 계정 유형과 익명 시험 식별자를 기록한다.
2. 공식 화면에서 자기 계정을 확인한다. Android·iOS 모두 로그인 후 정확한 본인 수치를 확보하면 자동으로 연결한다. iOS의 현재 검증은 합성 WKWebView 검사이며 실제 계정 연결은 미검증이다. 정확한 수·수집 시각을 같은 시점의 공식 화면과 비교한다. 축약 수를 정확한 정수로 바꾸어 기록하지 않는다.
3. 연결 창을 닫고 앱에서 수 수집을 다시 실행한다. 다른 프로필, 로그인 만료, 확인 화면, 응답 변경이 마지막 정상 기록을 덮어쓰지 않는지도 확인한다.
4. 작은·중간·큰 홈 화면 위젯을 추가하고 표시 계정을 선택한다. 앱의 저장값·시각·상태와 비교하고 위젯을 눌러 앱이 열리는지 확인한다.
5. 앱을 열지 않은 상태에서 실제 새 수치가 관측되는지 확인한다. 예약 요청 시각, 실제 요청 시각, 위젯 표시 시각을 구분한다. 전경 수집 경로는 전경 전용으로 기록한다.
6. 앱 재실행·기기 재시작·화면 잠금·네트워크 단절과 복구·절전 상태를 검사한다. iOS에서는 서명된 앱·위젯의 App Group·Keychain 공유도 확인한다.
7. 대상 SNS 연결을 해제하고 그 SNS의 세션·기록만 제거되는지, 다른 SNS와 늦게 완료되는 요청에 영향이 없는지 확인한다.

## 관계 명단

Instagram 후보 경로에서 한 페이지를 넘는 명단을 읽고 정상 커서 종료·중복 제거·계정 일치·필터링 여부를 확인한다. 시작과 종료의 수가 같아도 동시점 스냅샷임을 증명하지는 않으므로 비원자적 수집으로 기록한다.

참여자가 동의한 시험 계정의 수동 관계 변경으로 맞팔의 두 방향, 첫 스캔 기준 생성, 이탈 후보, 다음 정상 스캔에서의 연속 미관측을 확인한다. 앱이 계정 삭제·비활성화와 실제 언팔로우 원인을 구분했다고 보고하지 않는다. 중간 페이지 실패와 취소 뒤에는 이전 완료 명단이 유지돼야 한다.

## Android Instagram 자동 연결 — 2026-10-02

기존 API 36 로그인 기기의 앱을 데이터 보존 설치로 업데이트하고, Codex 사이드바 미러에서 Instagram 연결 창을 열었다. 기존 공식 로그인 세션이 유지됐으며 추가 인증 입력이나 연결 확인 버튼 없이 창이 닫히고 대시보드에 계정과 첫 수치가 표시됐다. 표시된 팔로워 수는 직전에 확인한 공식 본인 프로필의 정확한 수와 일치했다. 계정 식별자·사용자명·수치·화면 원본은 저장소에 기록하지 않는다.

읽기 전용 `ConnectionStatusDiagnostic`에서 Instagram의 세션 후보·연결 계정·수치 저장이 모두 true, 상태 `FOREGROUND_ONLY`, 경로 `instagram-webview-dom`임을 확인했다. 앱을 다시 실행한 뒤에도 저장된 계정과 수치가 표시됐다. 앞선 별도 데이터 요청은 HTTP 429였으므로 이 결과를 네이티브·백그라운드 요청 성공으로 취급하지 않는다. 실제 전체 관계 명단과 위젯의 새 값·자동 갱신은 이번 검사 범위에 포함하지 않았다. iOS는 변경하거나 다시 검사하지 않았다.

## Android 강제 중지와 앱 재개 후 복구 — 2026-10-03

기존 로그인용 API 36 에뮬레이터의 `799c0b9` 설치본에서 일반 예약을 잠시 15분으로 선택했다. 기존 세션으로 빠른 추적의 새 수집·위젯 반영을 확인하고 앱을 홈으로 내린 뒤, 공식 SDK의 `am force-stop`으로 앱을 강제 중지했다. 시험 전후 앱·AVD를 삭제하거나 데이터를 초기화하지 않았으며 로그인 기기에서 instrumentation을 실행하지 않았다.

강제 중지 상태로 약 17분 8초 동안 189개 표본을 관찰했다. `stopped=true`였고 빠른 추적 서비스·앱 전경은 실행되지 않았다. 일반 예약의 15분 간격이 지난 뒤에도 완료 주기 27과 마지막 정상 수치·관측 시각을 유지했다. 동일 연결, 저장된 완료 명단의 암호문과 세션 메타데이터도 보존됐다. 기존 홈 위젯은 숫자를 계속 표시하는 대신 OS가 회색으로 비활성화했다. 이는 [Android 15 이상 강제 중지 동작](https://developer.android.com/about/versions/15/behavior-changes-all?hl=en)과 일치한다.

사이드바의 앱 열기를 한 번 누르고 즉시 홈으로 내렸다. 수동 새로고침·빠른 추적 시작·예약 작업 강제 실행 없이 일반 예약이 재개돼 완료 주기가 28이 됐고, 04:24(Asia/Seoul)의 새 공식 본인 프로필 관측을 저장했다. 예약 실행 중 관찰한 표본에서 앱 전경과 빠른 추적 서비스는 모두 false였다. 홈 위젯이 정상 표시로 돌아오고 같은 수집 시각을 표시하는 것을 직접 확인했다. 빠른 추적은 자동 재시작하지 않았다.

## Android 스와이프 잠금과 배터리 절약 중 빠른 추적 — 2026-10-03

기존 로그인용 API 36 에뮬레이터에서 설치된 정상 APK가 `4a53bc9` 단계의 검증 APK와 같은지 확인했다. 일반 예약은 원래 60분을 유지하고, 수집 설정의 빠른 추적 시작을 눌러 기존 Instagram 세션의 새 공식 프로필을 읽었다. 앱을 홈으로 내린 뒤 읽기 전용 관찰에서 연결·완료 명단 암호문·세션 메타데이터, 실제 수집 시각, 서비스·예약·잠금·절전 상태를 기록했다. 앱·테스트 APK 재설치, DB·시계·라디오·절전 예외 목록 변경과 instrumentation은 실행하지 않았다.
