# 내 계정과 소셜 모아보기 위젯

2026-10-18 디자인 변경. 수집 방식·무료/프리미엄 실행 정책·계정 DB·로그인 세션은 변경하지 않는다.

| 종류 | Android | iOS | 내용 |
| --- | --- | --- | --- |
| 내 계정 | 기본 1×1, 40dp 최소 콘텐츠 영역, 크기 조절 가능 | `systemSmall` | SNS 하나의 공식 로고, 브랜드 배경, 팔로워 수, 실제 마지막 수집 시각 |
| 소셜 모아보기 | 기본 4×4, 최소 250×180dp로 조절 가능 | `systemLarge` | 모든 연결의 SNS·계정·팔로워·증감·수집 시각·비교 기준 시각 |

1×1은 Android 12 이상 런처의 목표 격자다. 실제 폭·높이·여백은 런처와 홈 격자에 따라 달라진다. 이전 Android는 최소 dp 크기를 사용한다. [Android 크기 메타데이터](https://developer.android.com/develop/ui/compose/glance/create-app-widget), [유연한 위젯 크기](https://developer.android.com/develop/ui/views/appwidgets/layouts)

## 표시와 선택

- 내 계정은 공식 벡터 아이콘과 SNS별 진한 그라데이션, 큰 숫자를 사용한다. Instagram은 보라·분홍, TikTok은 청록·분홍이 비치는 짙은 배경, X는 흑백, Facebook은 파랑, Reddit은 주황이다.
- 가장 작은 칸은 숫자·SNS·실제 수집 시각을 우선한다. 공간을 늘리면 계정명·증감·비교 시각을 추가한다. Android는 큰 시스템 글꼴에서도 좁은 칸의 배치로 전환한다.
- 정확한 수가 읽을 수 있는 크기로 들어가지 않으면 만·억·조·경 단위로 소수 둘째 자리까지 버림 표시한다. 예를 들어 `1,234,567,890`은 `12.34억`이다. 축약은 표시 전용이며 저장된 수와 접근성 설명은 정확한 수를 유지한다.
- 모아보기는 연결 개수를 표시하고 SNS별 배경과 로고로 행을 구분한다. Android에서는 공간이 부족하면 스크롤 목록을 사용한다. 안정적인 64비트 계정 ID로 갱신 중 스크롤 위치를 유지하며, 기존 `take(3)`/`take(5)` 제한을 제거했다. [Glance 목록](https://developer.android.com/develop/ui/compose/glance/build-ui#use-scrollable-layouts)
- iOS의 현재 개인 계정 저장 계약은 SNS마다 하나의 연결을 허용하므로 대형은 지원 SNS 다섯 개를 모두 표시한다. 페이지·같은 SNS의 복수 연결을 iOS에 도입할 때는 WidgetKit의 스크롤 불가 화면 크기에 맞춘 추가 설계가 필요하다.
- 성공하지 않은 시각을 갱신 시각으로 쓰지 않는다. 실패하면 마지막 수와 실제 관측 날짜·시각을 유지하고 상태를 설명한다. 작은 칸에는 상태 표시, 대형에는 실패 사유를 별도 줄로 표시하고 접근성 설명도 제공한다. 위젯 탭은 상태를 확인할 계정 화면을 연다.

## 미리보기와 추가

Android 앱의 미리보기는 실제 `TrackerWidgetContent`를 Glance `RemoteViews`로 렌더링한다. 별도의 Compose 모조 카드를 유지하지 않는다. 컬렉션을 지원하는 `AppWidgetHostView` 안에서 적용하며, API 26–31 앱 미리보기는 런처 위젯 ID 없이 같은 행을 전체 높이로 렌더링하고 앱 안에서 스크롤한다. 내 계정 선택만 소형에 적용하며 모아보기는 항상 모든 연결을 사용한다. 선택은 pin 성공 callback에서 위젯별로 저장한다. callback은 일회용 private 명시적 PendingIntent, widget ID, 두 provider의 종류를 검증한다. 재구성할 때 전역 최근 선택보다 해당 위젯의 저장된 선택을 우선한다.

iOS 앱과 확장도 같은 `TrackerWidgetContent`를 사용한다. 내 계정은 위젯 편집에서 SNS를 선택하고 모아보기에는 선택 메뉴를 두지 않는다. 실제 계정이 없는 미리보기는 연결 안내를 표시한다. 공식 SVG 에셋 카탈로그를 위젯 확장에도 포함한다.

## 기존 설치와 자원 사용

Android의 기존 `TrackerWidgetReceiver`와 계정 키를 유지한다. 기존 단일 계정 위젯은 같은 계정을 계속 표시하고, 종류 저장값과 계정 키가 모두 없는 기존 모아보기 위젯은 기존 크기에서 전체 연결 표시를 유지한다. 새 소형에서 계정이 제거됐을 때 다른 계정으로 자동 대체하지 않는다. 새 대형은 별도 provider다. iOS 소형의 기존 kind·SNS 선택을 유지하며, 이전 중형·대형 설치는 새 대형 종류로 다시 추가해야 할 수 있다.

Android의 수집 완료 갱신 병합은 두 provider 모두에 적용한다. 한 provider 갱신이 실패해도 다른 provider는 시도한다. 위젯은 최신 두 기록만 읽으며 추가 SNS 요청·주기 타이머·차트 전체 이력 조회를 만들지 않는다. 배경 이미지는 기기에서 만든 256×256 그림을 2MiB 캐시에 재사용하고 공식 아이콘은 앱 리소스에서 읽는다. iOS도 두 kind를 함께 reload하고 기존 시스템 갱신 정책을 유지한다. 실제 배터리·데이터 절감률을 측정한 변경은 아니다.

## 검증 경계

- JVM 회귀는 이전 선택 해석, 새 소형의 빈/삭제된 선택, 정확한 0, 만·억·조·경 경계와 올림 방지, Long 최대값, 목록 ID의 안정성과 기존 문자열 해시 충돌을 검사한다.
- Android 런타임 검사는 40×40·64×72·88×88dp 소형, 확장 크기, 다섯 SNS 표시, 오류 시 마지막 수·시각·비교 기준 보존, 긴 숫자 잘림을 대상으로 한다. 빈 계정·저장 오류의 초소형 안내와 시스템 글꼴 1.5·2배도 검사한다. 합성 fixture를 화면에만 전달하고 계정·세션·관측 DB에는 저장하지 않는다.
- Android 16 실기기의 분리된 검증 패키지에서 원래 회귀와 새 크기·목록·선택 검사를 실행했다. 최초에는 실제 글꼴의 span 폭·행 높이로 인한 숫자 말줄임/아래쪽 잘림과, 일반 FrameLayout에서 컬렉션 adapter가 적용되지 않는 문제를 재현했다. 실제 글자 폭·높이에 여유를 두고 `AppWidgetHostView`를 사용했다. 최종 검토에서 초소형의 빈 상태 안내가 중복돼 잘리는 실패도 재현하고 짧은 안내만 표시하도록 보완했다. 최종 23개가 실패·skip 없이 통과했다. 이 중 Compose 화면은 잠금 해제 후 실행했다. 합성 fixture 화면은 개인 앱·세션을 사용하지 않는다.
- 런처의 1×1·4×4 provider 메타데이터와 전체 일곱 항목의 실제 native adapter를 검사했다. 이 결과를 모든 런처의 손가락 스크롤·빈 홈 칸 배치·iOS 설치 검증으로 확대하지 않는다. [실행한 최종 검사](WORK_LOG.md)에 코드·빌드·실기기 범위를 구분한다.
