# 내 계정과 소셜 모아보기 위젯

2026-10-22 가로 배치·계정명 표시 옵션·글자 크기 보완. 수집 방식·무료/프리미엄 실행 정책·계정 DB·로그인 세션은 변경하지 않는다.

| 종류 | Android | iOS | 내용 |
| --- | --- | --- | --- |
| 내 계정 | 기본·최소 2×1, 최소 110×40dp, 크기 조절 가능 | 가로형 `systemMedium` | 큰 공식 로고·우측 팔로워 수·실제 수집 시각·선택형 계정명 |
| 소셜 모아보기 | 기본 4×4, 최소 250×180dp로 조절 가능 | `systemLarge` | 모든 연결의 큰 SNS 아이콘·우측 팔로워 수·수집 시각·선택형 계정명 |

2×1은 Android 12 이상 런처의 목표 격자다. 실제 폭·높이·여백은 런처와 홈 격자에 따라 달라진다. 이전 Android는 최소 dp 크기를 사용한다. [Android 크기 메타데이터](https://developer.android.com/develop/ui/compose/glance/create-app-widget), [유연한 위젯 크기](https://developer.android.com/develop/ui/views/appwidgets/layouts)

## 표시와 선택

- 내 계정은 공식 벡터 아이콘과 SNS별 진한 그라데이션, 큰 숫자를 사용한다. Instagram은 보라·분홍, TikTok은 청록·분홍이 비치는 짙은 배경, X는 흑백, Facebook은 파랑, Reddit은 주황이다.
- 아이콘과 팔로워 수를 가로로 배치하며 숫자는 우측 정렬한다. 계정명은 기본 숨김이고 내 계정·모아보기 각각 위젯별로 켜고 끈다. 증감·팔로잉·이전 수·비교 시각은 제외한다. Android는 작은 기존 호스트와 큰 시스템 글꼴에도 남은 폭·높이에 맞춰 숫자를 조절한다. 계정명을 숨기면 접근성 설명에서도 이름을 제외하며 정확한 수와 실제 수집 시각은 유지한다.
- 정확한 수가 읽을 수 있는 크기로 들어가지 않으면 만·억·조·경 단위로 소수 둘째 자리까지 버림 표시한다. 예를 들어 `1,234,567,890`은 `12.34억`이다. 축약은 표시 전용이며 저장된 수와 접근성 설명은 정확한 수를 유지한다.
- 모아보기는 연결 개수를 표시하고 SNS별 배경과 로고로 행을 구분한다. Android에서는 공간이 부족하면 스크롤 목록을 사용한다. 안정적인 64비트 계정 ID로 갱신 중 스크롤 위치를 유지하며, 기존 `take(3)`/`take(5)` 제한을 제거했다. [Glance 목록](https://developer.android.com/develop/ui/compose/glance/build-ui#use-scrollable-layouts)
- iOS는 개인 계정과 여러 Facebook 페이지를 같은 모아보기에 포함한다. 위젯 높이에 맞춰 표시할 행 수를 정하고, 모두 들어가지 않으면 이전·다음 버튼으로 모든 연결에 접근한다. 360pt 미리보기는 계정명 숨김일 때 세 행, 표시할 때 두 행으로 페이지를 나눈다. 큰 아이콘·글자·이름과 버튼 공간을 계산하며 더 많은 연결도 빠짐없이 순회한다. 계정을 해제하거나 저장된 위치가 범위를 벗어나도 유효한 마지막 묶음으로 보정해 빈 화면을 만들지 않는다.
- 성공하지 않은 시각을 갱신 시각으로 쓰지 않는다. 실패하면 마지막 수와 실제 관측 날짜·시각을 유지하고 상태를 설명한다. 작은 칸에는 상태 표시, 대형에는 실패 사유를 별도 줄로 표시하고 접근성 설명도 제공한다. 위젯 탭은 상태를 확인할 계정 화면을 연다.

## 미리보기와 추가

Android 앱의 미리보기는 실제 `TrackerWidgetContent`를 Glance `RemoteViews`로 렌더링한다. 별도의 Compose 모조 카드를 유지하지 않는다. 컬렉션을 지원하는 `AppWidgetHostView` 안에서 적용하며, API 26–31 앱 미리보기는 런처 위젯 ID 없이 같은 행을 전체 높이로 렌더링하고 앱 안에서 스크롤한다. 내 계정 선택만 소형에 적용하며 모아보기는 항상 모든 연결을 사용한다. 계정 선택과 계정명 표시 여부는 pin 성공 callback에서 위젯별로 저장한다. 앱 미리보기의 스위치는 새로 추가할 위젯에 적용하고, 기존 위젯은 길게 눌러 재구성한다. 두 provider 모두 표시 옵션의 구성 화면을 제공한다. callback은 일회용 private 명시적 PendingIntent, widget ID, 두 provider의 종류를 검증한다. 재구성할 때 전역 최근 선택보다 해당 위젯의 저장된 선택을 우선한다.

iOS 앱과 확장도 같은 `TrackerWidgetContent`와 페이지 계산을 사용한다. 앱 미리보기의 이전·다음 위치는 앱 화면에만 적용한다. 실제 모아보기 위젯의 표시 위치는 App Group에 보관하며, 모아보기 위젯을 여러 개 설치하면 이 위치를 공유한다. 내 계정은 위젯 편집에서 SNS와 계정명 표시 여부를 선택하며 모아보기는 계정명 표시 여부만 선택한다. 앱의 표시 스위치는 미리보기용이고 실제 위젯의 설정과 구분해 안내한다. [WidgetConfigurationIntent](https://developer.apple.com/documentation/appintents/widgetconfigurationintent)의 Bool 매개변수를 타임라인 엔트리까지 전달한다. 실제 계정이 없는 미리보기는 연결 안내를 표시한다. 공식 SVG 에셋 카탈로그를 위젯 확장에도 포함한다.

## 기존 설치와 자원 사용

Android의 기존 `TrackerWidgetReceiver`와 계정 키를 유지한다. 기존 단일 계정 위젯은 같은 계정을 계속 표시하고, 종류 저장값과 계정 키가 모두 없는 기존 모아보기 위젯은 기존 크기에서 전체 연결 표시를 유지한다. 새 소형에서 계정이 제거됐을 때 다른 계정으로 자동 대체하지 않는다. 새 대형은 별도 provider다. Android의 기존 1×1 배치는 자동으로 홈 공간을 재배치하지 않으므로 업데이트 후 2×1 이상으로 늘리거나 다시 추가한다. iOS는 기존 kind·SNS 선택 데이터를 유지하며 가로형 `systemMedium`을 지원한다. 이전 `systemSmall` 설치는 가로형으로 다시 추가해야 할 수 있다.

Android의 수집 완료 갱신 병합은 두 provider 모두에 적용한다. 한 provider 갱신이 실패해도 다른 provider는 시도한다. 위젯은 최신 두 기록만 읽으며 추가 SNS 요청·주기 타이머·차트 전체 이력 조회를 만들지 않는다. 배경 이미지는 기기에서 만든 256×256 그림을 2MiB 캐시에 재사용하고 공식 아이콘은 앱 리소스에서 읽는다. iOS도 두 kind를 함께 reload하고 기존 시스템 갱신 정책을 유지한다. 실제 배터리·데이터 절감률을 측정한 변경은 아니다.

## 이전 디자인의 검증 기록

- JVM 회귀는 이전 선택 해석, 새 소형의 빈/삭제된 선택, 정확한 0, 만·억·조·경 경계와 올림 방지, Long 최대값, 목록 ID의 안정성과 기존 문자열 해시 충돌을 검사한다.
- Android 런타임 검사는 40×40·64×72·88×88dp 소형, 확장 크기, 다섯 SNS 표시, 오류 시 마지막 수·시각·비교 기준 보존, 긴 숫자 잘림을 대상으로 한다. 빈 계정·저장 오류의 초소형 안내와 시스템 글꼴 1.5·2배도 검사한다. 합성 fixture를 화면에만 전달하고 계정·세션·관측 DB에는 저장하지 않는다.
- Android 16 실기기의 분리된 검증 패키지에서 원래 회귀와 새 크기·목록·선택 검사를 실행했다. 최초에는 실제 글꼴의 span 폭·행 높이로 인한 숫자 말줄임/아래쪽 잘림과, 일반 FrameLayout에서 컬렉션 adapter가 적용되지 않는 문제를 재현했다. 실제 글자 폭·높이에 여유를 두고 `AppWidgetHostView`를 사용했다. 최종 검토에서 초소형의 빈 상태 안내가 중복돼 잘리는 실패도 재현하고 짧은 안내만 표시하도록 보완했다. 최종 23개가 실패·skip 없이 통과했다. 이 중 Compose 화면은 잠금 해제 후 실행했다. 합성 fixture 화면은 개인 앱·세션을 사용하지 않는다.
- 런처의 1×1·4×4 provider 메타데이터와 전체 일곱 항목의 실제 native adapter를 검사했다. 이 결과를 모든 런처의 손가락 스크롤·빈 홈 칸 배치·iOS 설치 검증으로 확대하지 않는다. [실행한 최종 검사](WORK_LOG.md)에 코드·빌드·실기기 범위를 구분한다.

2026-10-18 실기기의 23개 통과는 그 날짜의 디자인 검증이다. 2026-10-19 소형 정보·로그아웃·복구 변경은 코드/빌드와 격리 저장 실험까지 확인했으며, 새 소형과 실제 세션의 기기 검사는 미실행이다. [현재 검증 범위](CONTINUITY_AND_LOGOUT.md)

## 2026-10-21 iOS 다중 페이지 접근

대형에 모든 행을 한꺼번에 배치하면 여러 Facebook 페이지가 추가될 때 위젯 높이를 넘을 수 있어 표시 범위와 페이지 조작을 추가했다. 데이터 목록을 다섯 개로 자르지 않으며 전체 연결 수를 표시한다. 버튼은 최소 44pt 영역과 이전·다음 접근성 이름을 사용하고 첫/마지막 묶음에서 불필요한 조작을 비활성화한다.

`OverviewWidgetPageIntent`는 앱을 열지 않고 표시 위치만 저장한다. 별도의 SNS 수집·위젯 reload 호출을 추가하지 않는다. [WidgetKit의 버튼 상호작용](https://developer.apple.com/documentation/widgetkit/adding-interactivity-to-widgets-and-live-activities)에 따라 완료 뒤 타임라인이 다시 읽히며, 기존 타임라인의 15분 수집 조건과 실패 대기는 유지한다. 버튼의 동작과 운영체제의 타임라인 재실행을 구분한다.

Swift 핵심 회귀 63개가 통과했으며, 새 6개는 300·338·360·420pt의 모든 연결 순회, 연결 삭제 뒤 위치 보정, 빈 목록·음수·잘못된 높이와 Int 최대값을 검사한다. iOS Debug 테스트 타깃과 서명 없는 Release 앱·위젯 빌드도 통과했다. 실제 iOS 홈 위젯의 버튼·장치별 배치·큰 글자·VoiceOver 조작은 기기 미실행이다.

## 2026-10-22 가로 배치·계정명 표시 옵션

Android 내 계정을 2×1 기준의 가로 배치로 바꿨다. 큰 아이콘은 좌측, 팔로워 수는 우측에 두고 하단에 실제 수집 시각을 표시한다. 내 계정과 모아보기의 증감·팔로잉·직전 수·비교 시각을 제거했다. 아이콘 내부 크기와 숫자·이름·시각 글씨를 키우고 긴 수치는 기존 정확값/표시용 축약 경계를 유지한다.

계정명은 기본 숨김이며 위젯별 설정으로 저장한다. Android 앱의 추가 미리보기와 pin callback, 두 종류의 구성/재구성 화면에 같은 옵션을 전달한다. iOS도 두 WidgetConfigurationIntent의 Bool 매개변수와 실제 타임라인에 연결하며 앱 미리보기와 홈 위젯 설정을 구분해 안내한다. 표시 옵션만 바꾸며 수집 주기·관측 DB·인증·과거 이력은 바꾸지 않는다.

Android core 47개와 app Debug/Release 단위 검사 각 111개, Debug·검사 APK·Release/R8·두 lint를 통과했다. lint 오류는 0개이며 기존 경고는 각각 16개다. Swift core 90개와 iOS Debug 검사 타깃·서명 없는 Release 앱/위젯 빌드도 통과했다. 새 core 검사는 계정명 표시로 행 높이가 달라져도 모든 연결을 빠짐없이 순회하는지와 잘못된 높이의 경계를 검사한다.

이름 숨김/표시·정확한 0·우측 숫자·각 SNS 아이콘·수집 시각과 긴 수치 접근성의 Android 렌더링 회귀, Compose 스위치 조작 및 iOS 두 표시 옵션의 렌더링 검사는 컴파일했다. 사용자의 코드·APK 준비 범위에 따라 기기·에뮬레이터를 실행하지 않았으므로 새 배치의 실제 홈 화면·편집 UI·큰 시스템 글꼴·VoiceOver/TalkBack 조작은 미실행이다. 이전 디자인의 실기기 통과를 이번 배치의 실행 결과로 확대하지 않는다.
