# Android WebView 연동 로그인

2026-10-03에 AI Quota의 현재 Android 로그인 구현을 읽고 팔로워 트래커의 공통 SNS 로그인 창에 적용했다. 참조한 파일은 `ProviderWebViewUserAgent.kt`, `ProviderLoginWebViewPolicy.kt`, `WebLoginActivity.kt`이며 참조 저장소의 HEAD는 `c0ec759d1d7d2645e010ced26f929a2c7ee4b4f9`다. AI Quota의 소스·사용자 변경·설치 상태는 수정하지 않았다.

## 로그인 창

- 현재 설치된 WebView의 기본 User-Agent에서 `; wv`와 `Version/4.0`만 조정한다. 기기·OS·Chrome 엔진 버전을 고정하거나 데스크톱 기기로 바꾸지 않는다.
- Google의 `accounts.google.com`과 Apple의 `appleid.apple.com`을 HTTPS 인증 이동으로 허용한다. 사용자 정보가 들어간 URL·비표준 포트·유사 호스트·다른 스킴은 차단한다.
- JavaScript 인증 팝업을 별도 WebView로 만든다. 부모와 팝업은 같은 CookieManager와 로그인 설정을 사용하며 `window.opener`·`postMessage`·`window.close` 동작을 유지한다. 동시 팝업은 최대 3개다.
- 현재 보이는 창에서 자동 연결을 검사한다. 팝업을 닫으면 원래 창으로 돌아가고, 로그인 창을 닫으면 부모·팝업을 모두 해제한다. 렌더러 종료 후에는 새로고침으로 로그인 창을 다시 만든다.
- 주 문서의 초기 팝업 요청과 POST 이동도 허용 주소를 검사한다. TLS 오류는 취소하고 파일·콘텐츠 접근, 웹 디버깅과 콘솔 원문 출력은 계속 차단한다. 로그인 창의 화면 캡처 보호는 유지한다.

## 데이터 수집 경계

인증 페이지의 허용은 데이터 수집 호스트의 확장이 아니다. `Provider.allows`, `SessionStore.header`, 본인 ID 확인과 정확한 수치 확인은 그대로 사용한다. Google·Apple 페이지에서는 자동 연결이나 팔로워 캡처를 시작하지 않는다. 캡처 도중 인증 페이지로 이동한 경우 SNS 캡처의 정리 스크립트도 실행하지 않는다.

쿠키가 존재하는 것만으로 연결을 저장하지 않는다. 사용자가 SNS로 돌아오고 로그인한 본인 계정과 수치가 확인되면 기존 연결·암호화 저장·위젯 갱신 경로로 연결을 완료한다. Google의 인증 URL, 폼 입력값, 비밀번호, 쿠키 원문은 진단 파일·로그·fixture·커밋에 저장하지 않는다.

## 검증 해석

합성 HTTPS 페이지와 별도 QA 에뮬레이터로 현재 엔진 버전 보존, 인증 호스트와 수집 호스트 분리, 팝업의 설정·opener·복귀·해제, Google 페이지의 자동 연결 차단과 SNS 본인 페이지의 자동 연결, 기존 화면 표시·터치·요청 제한·본인 ID 검사를 수행한다. HTTPS fixture는 실제 로그인 WebViewClient의 허용 주소 검사를 거치고 다른 네트워크 요청은 모두 차단한다.

실제 사이트의 Google 버튼과 인증 페이지 진입은 별도로 확인한다. 인증 화면을 연 것과 실제 사용자가 자격증명·추가 인증을 완료하고 SNS 세션 및 팔로워 수를 확보한 것은 구분한다. 이 변경은 Android 로그인 창에 적용하며 iOS의 인증 동작을 검증한 결과로 표시하지 않는다.

AI Quota의 호환 설정을 적용해도 Google의 공식 WebView OAuth 지원을 의미하지 않는다. [Google OAuth 정책](https://developers.google.com/identity/protocols/oauth2/policies)은 개발자가 제어하는 embedded user-agent를 허용하지 않는다. 사이트·WebView 버전·계정 조건에 따라 거절될 수 있으며, 실제 관측 범위만 지원 검증으로 기록한다.

### X 로그인 완료 후 연결 창이 남는 문제 — 2026-10-03

Android 16 / API 36의 Samsung SM-F966N 실기기, WebView `154.0.8037.57`에서 X 로그인 세션이 있어도 연결 창 하단에 “로그인을 완료해주세요”가 남는 문제를 확인했다. 실제 페이지에는 데스크톱 프로필 링크와 전역 `__INITIAL_STATE__` 객체가 없었고, 초기 계정 JSON을 포함한 인라인 스크립트는 남아 있었다. 기존 수집기는 이 구조를 읽지 못해 계정 정보 누락을 미로그인으로 처리했다.

X의 현재 전역 상태 또는 남아 있는 초기 JSON에서 쿠키의 본인 ID와 일치하는 사용자 레코드만 읽도록 수정했다. 초기 스크립트는 크기를 제한해 JSON 부분만 파싱하며 실행하지 않는다. 정확한 수가 없고 본인 사용자명이 확인되면 기존 자동 연결 흐름으로 본인 프로필을 연다. 축약 수치·다른 사용자 ID·다른 출처의 링크는 연결 수치로 저장하지 않는다. 로그인 세션이 확인된 뒤 계정 문맥만 누락된 경우에는 재로그인을 요구하는 안내와 구분한다.

기존 로그인과 앱 데이터를 보존해 Debug APK를 업데이트했다. 실기기의 명시적인 단일 진단에서 본인 ID 일치, 정확한 정수 수치와 자동 연결 콜백을 확인했다. 이어 실제 앱의 SNS 연결에서 X를 선택했을 때 재로그인이나 연결 확인 버튼 없이 로그인 창이 닫히고 계정 탭에 X 카드와 팔로워 수가 표시됐다. 앱 프로세스 재시작 후 읽기 전용 저장 검사는 계정·수집 기록 존재와 쿠키 본인 ID 일치를 확인했으며, 상태는 `FOREGROUND_ONLY`, 출처는 `x-webview-profile`이었다. 진단 출력에는 상태와 불리언만 포함하고 계정명·ID·수치·쿠키·원시 DOM은 포함하지 않았다.

이 결과는 해당 실기기의 기존 X 로그인과 전경 자동 연결에 대한 검증이다. X의 로그인 방법별 전체 인증 완료, 백그라운드 반복 수집, 실제 홈 위젯 반영이나 iOS의 실제 X 세션을 검증한 결과로 확대하지 않는다.

공통 캡처 24개·Android core 36개·app 24개 검사가 통과했고, Debug·Release(R8) 빌드·Debug/Release lint·테스트 APK 빌드도 통과했다. 두 lint는 오류 0개이며 기존 경고 3개가 유지됐다. 실기기 설치 APK가 최종 Debug 산출물과 일치하는지 확인했다. 에뮬레이터나 Android Studio를 다시 실행하지 않았다.

### TikTok 로그인 후 외부 앱 링크가 차단되는 문제 — 2026-10-03

같은 Samsung SM-F966N / API 36 / WebView `154.0.8037.57` 실기기에서 사용자가 Google 인증을 완료하고 TikTok 웹사이트로 돌아왔을 때 SNS 인증 쿠키가 확인됐다. 이어 공식 웹페이지가 `snssdk1340` 스킴과 `aweme`·`user` 호스트로 외부 TikTok 앱을 열려고 했다. 기존 일반 주소 차단이 이 선택적인 앱 이동에도 로그인 실패 안내를 표시했다.

공식 TikTok HTTPS 페이지에서 발생하는 해당 앱 링크를 WebView 안에서 소비해 현재 로그인 문서를 유지하도록 수정했다. 같은 기기의 설치된 TikTok 패키지에 등록된 `snssdk1233`·`snssdk1180` 스킴에도 같은 제한을 적용한다. 이 세 스킴과 두 호스트만 처리하며 외부 앱을 실행하지 않는다. HTTPS 페이지 허용·본인 계정 확인·수집 쿠키 경계는 유지한다. 다른 출처·위장 호스트·사용자 정보·명시적 포트·알 수 없는 스킴은 계속 차단한다.

이 문제의 진단은 메모리 안의 이동 스킴·호스트, 인증 여부와 고정된 상태 플래그만 사용한다. 경로·쿼리·OAuth 코드·폼 입력값·쿠키·원시 DOM·계정명·ID·팔로워 수를 출력하지 않는다. `TikTokAppLinkRuntimeTest`는 네트워크를 fixture로 차단하고 기존 개인 세션이나 앱 저장소를 변경하지 않으며, 선택적인 앱 링크의 현재 문서 보존과 다른 주소의 차단을 검사한다.

확보된 세션으로 실제 앱의 SNS 연결에서 TikTok을 선택했을 때 연결 확인 버튼이나 재로그인 없이 로그인 창이 닫히고 계정 탭의 TikTok 카드와 수치가 나타났다. 데이터 보존 상태로 수정 APK를 설치한 후 읽기 전용 저장 검사는 인증·계정·수집 기록 존재와 저장된 본인 ID 일치를 확인했다. 상태는 `FOREGROUND_ONLY`, 출처는 `tiktok-webview-profile`이며 기존 X 연결과 기록도 남아 있었다. 이 검사는 해당 실기기의 Google 인증 및 전경 연결 범위이며, 다른 로그인 방식·백그라운드 반복 수집·실제 홈 위젯·iOS의 성공을 뜻하지 않는다.

공통 캡처 24개·Android core 36개·app 28개 검사가 통과했다. 같은 실기기에서 선택적인 앱 링크 6가지 조합의 문서 보존, 다른 HTTPS 주소 차단, 위장된 앱 링크 차단의 런타임 검사 3개와 읽기 전용 저장 검사 1개가 통과했다. Debug·Release(R8)·테스트 APK 빌드와 Debug/Release lint가 통과했으며 두 lint는 오류 0개와 기존 경고 3개다. 설치된 APK가 수정 Debug 산출물과 일치하는지 확인했다. 수정 APK에서 실제 SNS 화면 복귀를 한 번 더 시각적으로 확인하는 단계는 휴대폰 자동 잠금 때문에 대기 중이며, 이 미확인 단계를 런타임 fixture나 저장 검사로 대체해 완료로 표시하지 않는다.

### Facebook 로그인 후 수치를 확보하지 못하는 문제 — 2026-10-04

같은 실기기의 Facebook 인증 쿠키와 본인 ID는 남아 있었지만, 로그인 후 홈 화면에는 기존 수집기가 요구하는 프로필 JSON이 없었다. 본인 프로필을 열면 Facebook이 외부 앱용 `intent://profile/` 링크를 보냈고 일반 이동 경계가 이를 차단했다. 이 링크에는 공식 HTTPS 프로필의 `browser_fallback_url`이 포함돼 있었다. 웹 프로필에서는 정확한 팔로워 수가 JSON이나 앵커 링크 대신 계정 제목 옆의 `role="button"` 영역에 표시됐다. 공통 메뉴도 별도 H1을 사용하므로 첫 제목을 계정 제목으로 사용할 수 없었다.

수치가 없는 홈에서는 쿠키의 본인 ID로 공식 프로필을 한 번 연다. 공식 Facebook HTTPS 문서에서 발생한 프로필 intent의 `fb` 스킴·공식 패키지·HTTPS 대체 주소를 확인한 후 같은 WebView 안에서 대체 주소를 연다. 외부 Facebook 앱은 실행하지 않는다. 대체 주소는 공식 도메인의 `/profile.php`로 제한하며 중복 이동이나 2회를 넘는 대체 이동은 중단한다. 다른 출처·스킴·패키지·유사 호스트·사용자 정보·비표준 포트·중복된 intent 값은 허용하지 않는다.

프로필 DOM은 공식 주소와 유일한 본인 ID 쿼리 또는 검증한 본인 사용자명을 먼저 확인한다. 계정 제목과 팔로워 버튼이 함께 있는 작은 영역만 읽고, 메뉴 제목·게시물·feed·친구 수·다른 영역의 수·축약 값은 사용하지 않는다. 수치 영역이 여러 개거나 값이 충돌하면 연결을 저장하지 않는다. 정확한 0은 정상 수치로 보존한다. 기존 JSON 수집과 `facebook-webview-profile` 출처 계약, 암호화 저장, 일반 로그인 경계는 유지한다. 명시적 연결 재시도는 본인 프로필 이동 이력을 초기화한다.

기존 로그인으로 실제 앱의 SNS 연결에서 Facebook을 선택했을 때 연결 확인 버튼이나 재로그인 없이 로그인 창이 닫혔고, 계정 탭의 Facebook 카드에 숫자와 상대 갱신 시각이 표시됐다. 앱 프로세스 재시작 후 저장 검사는 인증·계정·수 기록 존재와 쿠키 본인 ID 일치를 확인했다. 상태는 `FOREGROUND_ONLY`, 출처는 `facebook-webview-profile`이며 기존 X·TikTok 연결과 수 기록도 보존됐다. 전체 개인정보·수치·쿠키·원시 DOM을 출력하지 않고 상태와 구조 플래그만 검사했다. 최종 검사 결과는 [기기 검증](DEVICE_VALIDATION.md#facebook-로그인-후-자동-연결--2026-10-04)에 기록한다.

이 결과는 해당 기기의 로그인한 Facebook 프로필 1개와 전경 연결에 대한 검증이다. 다른 계정 유형·로그인 방법 전체·Facebook 페이지 계정·명단·백그라운드 1분 수집·실제 홈 위젯의 반복 갱신·iOS의 실제 Facebook 세션을 검증한 결과로 확대하지 않는다.
