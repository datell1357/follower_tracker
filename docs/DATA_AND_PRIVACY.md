# 현재 구현의 데이터 처리

이 문서는 구현된 데이터 흐름을 설명한다. 실제 SNS 세션·연결 해제·기기 잠금 검사는 [기기 검증 기록](DEVICE_VALIDATION.md)에서 확인한다. 공개 배포용 설명에는 검증한 지원 범위와 게시자 정보를 반영해야 한다.

## 로그인과 요청

사용자는 앱 안에서 SNS의 공식 HTTPS 페이지에 직접 로그인한다. 비밀번호·추가 인증 코드는 SNS 페이지로 입력하며, 팔로워 트래커는 로그인 입력 필드를 읽거나 저장하지 않는다. SNS의 로그인 페이지와 그 페이지가 불러오는 리소스는 해당 SNS의 서비스와 통신한다.

앱이 SNS 데이터를 수집하는 요청은 허용된 SNS 목적지의 읽기 요청이다. 쿠키는 요청 URL의 도메인·경로·HTTPS 범위에 맞게 사용한다. 웹 화면 수집기는 로그인 후 자기 계정 ID와 일치하는 프로필 정보만 처리한다. 앱에 수집기 코드를 포함하며 임의의 실행 코드를 서버에서 내려받지 않는다.

팔로워 트래커의 서버·유료 API·구독·분석 SDK·자동 오류 업로드는 현재 구현에 없다. 기기에 저장한 쿠키나 명단을 개발자에게 전달하는 기능도 없다.

## 저장하는 자료

| 자료 | Android | iOS |
| --- | --- | --- |
| 로그인 쿠키 | 앱 전용 CookieManager/WebView 저장소 | Keychain. 로그인 WKWebView는 비영구 데이터 저장소를 사용 |
| 요청에 필요한 사용자 에이전트·자기 ID·저장 시각 | Android Keystore 키로 암호화한 앱 내부 설정 | 쿠키와 함께 Keychain에 저장 |
| 연결한 SNS·계정 식별자·이름·프로필 URL·지원/오류 상태 | 앱 내부 Room DB | 앱·위젯 App Group의 SQLite DB |
| 팔로워·팔로잉 수·수집 시각·정밀도·수집기 버전 | Room DB | App Group SQLite DB |
| 완료된 팔로워·팔로잉 명단 | Android Keystore 키를 사용한 AES-GCM 암호문 | Keychain의 키를 사용한 AES-GCM 암호문을 App Group DB에 저장 |
| 수집 간격과 예약 작업 상태 | 앱 내부 설정 및 WorkManager | App Group 설정 및 운영체제 백그라운드 예약 |

Android 세션 메타데이터의 암호화와 WebView 자체 쿠키 저장소를 구분한다. WebView 쿠키를 별도로 Keystore 암호문으로 저장한 것으로 설명하지 않는다. iOS 앱·위젯은 같은 App Group과 Keychain 그룹을 사용하며, 위젯 화면은 수치·계정·마지막 수집 시각·상태만 표시한다. 사람별 관계 명단은 위젯 화면에 표시하지 않는다.

Android 앱은 OS 백업과 기기 전송에서 앱 데이터를 제외하도록 구성했다. iOS DB 디렉터리는 백업 제외와 첫 잠금 해제 이후 접근 보호를 설정하고, Keychain 항목은 `AfterFirstUnlockThisDeviceOnly`로 저장한다. 실제 기기의 잠금·전송 동작은 별도 검증 대상이다.

현재 수집 기록은 연결 해제까지 DB에 누적된다. 화면 조회는 최근 수치 366개와 관계 비교에 필요한 최신 명단을 사용하지만, 조회 제한이 오래된 DB 행 삭제를 뜻하지 않는다. 재설치 시 Keychain을 별도로 초기화하는 코드는 없으므로, OS의 앱 제거 동작을 세션 삭제 검증으로 대신하지 않는다.

## 연결 해제와 실패 처리

설정에서 연결을 해제하면 확인 창을 거쳐 대상 계정의 수치·관계 기록을 제거하고 해당 SNS 세션을 제거한다. Android는 대상 SNS의 관측·알려진 쿠키와 웹 저장소를 정리하며 전역 쿠키 초기화를 사용하지 않는다. iOS는 대상 SNS의 Keychain 세션을 제거한다. 다른 SNS의 연결과 기록은 유지하는 구조다. 실제 로그인 상태가 해제되는지는 SNS·OS별로 검사한다.

연결 해제 뒤 완료되는 네이티브 요청은 계정을 다시 만들거나 과거 세션을 저장하지 않도록 막는다. 같은 계정을 다시 연결해도 이전 연결에서 시작한 요청의 수치·상태·명단을 새 기록에 반영하지 않는다. 수집 실패 때는 마지막 성공 수와 완료된 명단을 유지한다. 로그인 만료·추가 확인·응답 변경이 발생하면 자동 요청을 멈추고 사용자에게 상태를 표시한다.

원시 쿠키·응답 전체·로그인 입력·사람별 명단을 앱 진단 로그나 저장소 fixture에 남기지 않는다. Android 로그인 창은 화면 캡처를 제한하며 WebView 검사·콘솔 출력을 비활성화했다. 시험 자료는 빈 화면 또는 명시적인 합성 값으로 만들고 `.local/`에 보관한다.
